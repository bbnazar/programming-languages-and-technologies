## 1. Цель
Изучить различие аутентификации и авторизации, жизненный цикл сессии; реализовать вход/выход и защиту ресурсов по принадлежности (запрет горизонтального доступа к чужим задачам).

## 2. Анализ требований и схема

Пользователи: `anna`, `boris`. Ресурс: задачи. Начальные данные: задача №1 принадлежит Анне, №2 принадлежит Борису.

```
Браузер → POST /login → проверка логина и bcrypt-хеша → сессия + cookie (HttpOnly)
        → GET /api/tasks → только задачи текущего пользователя
        → GET/PATCH/DELETE /api/tasks/:id → проверка владельца:
              нет входа → 401, задачи нет → 404, чужая задача → 403
        → POST /logout → сессия уничтожена
```

## 4. Описание реализации
- **Сервер:** вход проверяет пустые поля (400) и пароль через `bcryptjs` (401), затем `session.regenerate()`. `requireAuth` возвращает 401 без сессии. `loadOwnTask` подключён ко всем маршрутам `/api/tasks/:id` и возвращает 404 (нет задачи) или 403 (чужая). `GET /api/tasks` фильтрует задачи по владельцу. Срок сессии 15 минут.
- **Клиент:** форма входа, список личных задач, добавление, отметка «Готово», удаление, индикатор времени сессии, кнопки «Открыть задачу №1/№2» для демонстрации 403.

## 7. Меры безопасности
- bcrypt-хеши паролей; открытых паролей и реальных данных в проекте нет.
- Cookie `HttpOnly`, `SameSite=Lax` (при HTTPS — `Secure`).
- Проверка владельца на сервере при каждом обращении к задаче, а не только фильтрация списка на клиенте.
- Различаются 401 (не аутентифицирован), 403 (нет прав), 404 (нет ресурса).
- Названия задач выводятся через `textContent` (защита от XSS).
- `session.regenerate()` при входе, `session.destroy()` при выходе.
- Данные в памяти сбрасываются при перезапуске (учебный прототип).

## 8. Творческое задание
**Индикатор оставшегося времени сессии:** клиент показывает обратный отсчёт и по окончании возвращает на форму входа. Это снижает риск потери действий из-за неожиданного завершения сессии.

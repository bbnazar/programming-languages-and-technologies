# Ответы на контрольные вопросы (лабораторная работа №12)

1. **Чем аутентификация отличается от авторизации?**
   Аутентификация отвечает на вопрос «кто вы?» (проверка логина и пароля), авторизация — «что вам разрешено?» (проверка прав на ресурс или действие).

2. **Что такое JWT и из каких частей он состоит?**
   JSON Web Token — компактный токен формата `header.payload.signature`. Header содержит алгоритм подписи, payload — claims (кто, срок действия и т.д.), signature — подпись, по которой сервер проверяет целостность и подлинность.

3. **Шифрует ли JWT содержимое payload?**
   Нет. Header и payload лишь кодируются Base64URL, их может прочитать любой. Подпись защищает от подмены, но не скрывает данные, поэтому секреты и пароли в payload помещать нельзя.

4. **Что такое серверная сессия?**
   Состояние пользователя, которое хранится на сервере. Клиенту выдаётся только идентификатор сессии в cookie, по нему сервер находит данные. Сессию можно в любой момент уничтожить на сервере.

5. **Зачем нужны HttpOnly и Secure для cookie?**
   `HttpOnly` запрещает чтение cookie из JavaScript, что мешает украсть сессию при XSS. `Secure` отправляет cookie только по HTTPS, защищая от перехвата в сети.

6. **Почему localStorage не рекомендуется для хранения чувствительных токенов?**
   Любой JavaScript на странице (в том числе внедрённый через XSS) может прочитать localStorage и отправить токен злоумышленнику. Cookie с HttpOnly для скриптов недоступна.

7. **Чем OAuth 2.0 отличается от OpenID Connect?**
   OAuth 2.0 — протокол делегированной авторизации (доступ приложения к ресурсам от имени пользователя). OpenID Connect — надстройка над OAuth 2.0, добавляющая аутентификацию: ID-токен с информацией о пользователе.

8. **Что такое access token и refresh token?**
   Access token — короткоживущий токен для обращения к защищённым ресурсам. Refresh token — долгоживущий токен, по которому получают новый access token без повторного ввода пароля; его нужно хранить особенно бережно и ротировать.

9. **Зачем проверять срок действия JWT?**
   Чтобы ограничить время, в течение которого украденный или устаревший токен можно использовать. Токен без проверки `exp` оставался бы валидным бесконечно.

10. **В чём различие HTTP 401 и 403?**
    401 Unauthorized — пользователь не аутентифицирован (нет входа или сессия недействительна). 403 Forbidden — пользователь известен, но прав на ресурс или действие у него нет.

11. **Почему нельзя полагаться только на скрытие кнопки в интерфейсе?**
    Клиентский код можно изменить, а запросы к API отправить напрямую (консоль, curl). Реальную защиту обеспечивает только проверка прав на сервере.

12. **Что должно происходить при выходе пользователя?**
    Сервер уничтожает сессию (или отзывает токены), cookie удаляется, повторный запрос к защищённому ресурсу возвращает 401, клиент показывает форму входа.
